L1 — Foundation, Messages & Doctor

After L1, a freshly-installed user can run sb doctor, browse sb message list, and trust that the message schemas every later level depends on are locked in. No transports yet, no codegen yet — just the contract everything else builds on.

Scope

sb-core — pure logic, zero IO

  • TopicName parser/validator for /<device>/<workspace>/<module>/<transport>/<topic> where <transport> is the literal iox2 or zenoh.
  • Serde types — file ↔ Rust type:
    • SbCliConfig ← sb.config.yml (CLI's own settings: tool paths, defaults)
    • ModuleDevConfig ← sb.dev.yml (per-module dev interface)
    • ModulePrdConfig ← sb.prd.yml (per-module production interface)
    • WorkspaceFlow ← flow.yaml (workspace module registry — defined here, first used at L2)
  • Transport::{Zenoh, Iceoryx2} enum with per-transport key/service-name derivation.
  • SbCliConfig::merge(env_override, workspace, global) — pure layered loader.

sb.config.yml loader

  • Reads (highest priority first):
    1. $SB_CONFIG env var (explicit path; tests / CI / ad-hoc)
    2. <active_workspace>/sb.config.yml (L2 will start populating this)
    3. ~/.swarmbotix/sb.config.yml
    4. Built-in defaults
  • Missing paths surface as explicit errors from sb doctor — never silently swallowed.

Message vault

  • Forge-bundled messages/ros2/message_definitions/ at repo root — source of truth for std/*. Embedded into the sb binary via include_dir!. std/ ships in the ros2 style.
  • Per project_message_split:
    • std/Header.proto — metadata only. Includes metadata.msg_freq_desired so any future *Stamped message can advertise its intended Hz to topic-list at L4.
    • std/String.proto — bare payload (mirrors ROS2 std_msgs/String)
    • std/StringStamped.proto — Header + String composite
    • Same pattern for Twist, Image, PointCloud, etc.
  • Install-on-first-run: first invocation that touches the vault copies std/* from the embedded bundle into ~/.swarmbotix/messages/ros2/message_definitions/std/ if absent. Idempotent. Never overwrites user edits.
  • Vault CRUD: 
    sb message list            # walk vault, print names
sb message new <Name>      # write .proto skeleton under user namespace
sb message rm  <Name>      # delete file (refuse if under std/)
sb message compile         # protoc all → cache dir
sb message compile <Name>  # protoc a single message
  • Vault lookup API (used by every later level): fn schema(name: &str) -> Option<MessageSchema> backed by the protoc-generated FileDescriptorSet.

Doctor & config commands

  • sb doctor — reads merged sb.config.yml, validates every declared path:
    • protoc --version succeeds (libprotoc 35.0 currently)
    • flatc --version succeeds
    • libzenohc.so, libiceoryx2_ffi_c.so: file exists, dlopen succeeds
    • tmux (or psmux on Windows) on PATH
    • ~/.swarmbotix/messages/ros2/message_definitions/std/ populated; offers to re-install from embedded bundle if missing
  • sb config — open merged sb.config.yml in $EDITOR.
  • sb config set <key> <value> — write to global file. --workspace writes to active workspace (no-op until L2 lands).

TDD plan

1. Topic name parser table test
20+ fixtures covering valid forms and each failure mode (missing leading slash, wrong segment count, illegal chars, empty segment). Drive TopicName::parse(); assert each fixture maps to the expected Ok / Err(variant). crates/sb-core/src/topic.rs.
2. YAML round-trip per config type
For each of SbCliConfig, ModuleDevConfig, ModulePrdConfig, WorkspaceFlow: from_str → struct → to_string → from_str must be a fixed point. Catches accidental schema drift before any downstream code depends on it.
3. SbCliConfig::merge + env override
Pure-function tests: $SB_CONFIG wins outright over both workspace and global; workspace overrides global; missing keys fall through; all missing returns built-in default. Five fixture pairs, exact-match assertion.
4. Vault CRUD round-trip
Tempdir $HOME: new("custom/Foo") → list contains "custom/Foo" → rm → list does not. rm on std/* refused with explicit message. Name validator rejects non-PascalCase leaf, illegal namespace chars.
5. Install-on-first-run
Fresh tempdir $HOME; first sb message list populates std/* from embedded bundle. Second call is a no-op. User-edited std/Header.proto is preserved across re-runs (no clobber).
6. protoc invocation
sb message compile std/Header with a valid protoc path produces a non-empty FileDescriptorSet. With $SB_CONFIG pointing at a config with a bogus path, fails non-zero with "protoc not found at <path>".
7. Header / String split fixture
Golden test on std/Header.proto, std/String.proto, std/StringStamped.proto — fields exactly as project_message_split specifies. Header must contain metadata.msg_freq_desired; if someone "fixes" Header to include a payload, this test breaks loudly.
8. Every std/* compiles to Rust
Loop over std/*.proto, run protoc with the Rust plugin, cargo check in a scratch crate. Python/C++/Dart/C# proof-of-compile lands at L3 once language codegen exists.
9. Vault lookup API
schema("std/Header") returns Some with expected field names & types. schema("does/not/exist") returns None. Used by every later level for type validation.
10. sb doctor happy path + failure modes
Stub PATH with working protoc, flatc, tmux; sb doctor exits 0, one OK line per check. Strip protoc from PATH AND unset its sb.config.yml entry → exit non-zero, message names "protoc". Provide invalid .so path → exit non-zero, message contains the bad path. Each missing dep reported separately, not stopping at the first.

Why this is L1

  • Messages are the load-bearing contract every later level reads from. Locking the Header / Stamped split early prevents app authors writing code against a transient shape.
  • The Header's metadata.msg_freq_desired field is the single design decision that lets L4 topic list show real rates without a wire-format wrapper. Bake it in here.
  • Pure-logic types (sb-core) are the substrate for every subsequent level. Building them in isolation (zero IO) keeps the unit-test surface fast.
  • sb doctor lives here so a fresh installer can verify their toolchain on day 1 — before writing any app code.
